## [v12.20] - 2026-11-07

### 修复：自定义通道发图，图片被误替换为占位符（模型根本没收到图）

- **现象**：链路诊断「文本 ✓ · 看图 ✓」全过，但聊天里发图，星语仍回「我虽然看不见画面（系统暂时无法接收图像）」——且这次是模型自己生成的（有人设口吻），不是本地模板
- **根因**：`buildMessages()` 的看图判定 `!!pv.vision` 与 `aiChat()` 预检 `pv.vision !== null` 不一致——自定义通道 `vision:''` 为 falsy，被误判为不支持看图，当前消息的图片在请求前就被替换成 `[用户之前发过一张图片]` 占位符；模型收到占位符后顺着人设描述"看不见"
- **修复**：`canSee` 判定统一为 `pv.vision !== null`，与预检一致（custom 放行，deepseek/remote/proxy 仍过滤历史图片）
- **配套**：SW 缓存 v32 → v33；版本条 v12.20

  - 新增 `.set-test-status.raw` 样式：长报错改小字左对齐、可换行，深浅主题均适配

## [v12.16] - 2026-11-07

### 修复：换服务商后请求地址残留导致 404

- **现象**：用户切到「通义千问」发图，报「接口地址不对（404）」；但实测 dashscope 接口存活（错误 Key 返回 401 invalid_api_key，路径无误）——说明请求根本没打到官方地址
- **根因**：请求直接用 `aiCfg.endpoint`（localStorage 持久化）。此前选「后端中转」或「自定义」时保存的旧地址残留，切换服务商若未重新保存，请求仍发往旧地址 → 404
- **修复**：
  - `03-ai-core.js`：请求时内置服务商一律改用 `AI_PROVIDERS[provider].endpoint` 官方地址，仅 `custom` 信任用户自填地址
  - `04-sensory.js`：保存设置时同步把内置服务商的官方地址写回 `aiCfg.endpoint`（链路诊断显示也随之矫正）
  - `aiErrText`：404 文案补充「或模型名不存在」
- **配套**：SW 缓存 v28 → v29；版本条 v12.16
- **验证**：两个 JS 语法检查通过

## [v12.14] - 2026-11-06

### 修复：看图失败时挂出与图片无关的「依据」

- **现象**：发图片但模型看不了时，降级回复底部仍挂着两条引用（《去医院检查要准备什么》《为什么叫"星星的孩子"》）——它们只是按用户那句"请帮我看看这张图片"文字检索出来的，跟图片内容毫无关系，等于给出了错误证据

  - 看图轮次不检索、不注入：`buildMessages()` 跳过 `ragContext()`，预检索改为 `image ? [] : searchKB(text)`
  - 带图失败改走专用兜底：明确说明"图片没看到"，给出切换通义千问 / 改用文字描述两条路径，并以 `cites:false` 渲染，不再显示依据；同时不记入未命中清单（问题不在知识库覆盖范围）
- **配套**：SW 缓存 v26 → v27；版本条 v12.14

## [v12.13] - 2026-11-06

### 修复：图片消息在非视觉模型下反复 400

- **现象**（真实使用中发现）：向星语发图片后，若当前模型不支持看图（如 deepseek-chat），除了当场失败，历史消息里的图片还会随之后每一轮请求一起发出，导致后续纯文字提问也持续报 HTTP 400、一直降级到本地知识库
- **修复**（`03-ai-core.js`）：
  - `buildMessages()` 按"当前模型是否支持视觉"过滤历史：不支持时自动把历史图片降级为文字占位「[用户之前发过一张图片]」，图片不再进入请求体

  - 带图请求失败且错误为 400 时，降级提示追加引导："切换到「通义千问」我就能看图啦"
- **原有防线保留**：发图时的服务商预检（vision 为空的模型直接温和拦截并给切换建议）不变
- **配套**：SW 缓存 v25 → v26；版本条 v12.13
